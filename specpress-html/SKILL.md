# SpecPress HTML

## 内容组织方式

按当前主题选择对应结构，不要求每份文档同时包含接口、数据库和目录。

**接口**

- 按业务模块分组，每组一个标题和一张表；每个接口占一行。
- 列顺序统一为「操作｜方法｜请求字段｜响应字段」；「方法」列同时展示 HTTP 方法与完整接口路径。
- 请求和响应字段使用紧凑列表，一项对应一个字段；字段名与简短含义并列，必要时补充类型、可选条件、取值或默认值。
- 嵌套字段使用一致的路径表示，如 `items[].id`；避免用大段 JSON 代替字段说明。

**数据库**

- 每张表独立分组，标题使用表名，可并列展示已有的业务名称；必要时用一句短句说明一行代表什么。
- 列顺序统一为「字段｜类型｜可空｜默认值｜业务含义｜约束」；每个字段占一行。
- 主键、唯一性、关联与取值限制放在约束列；不混入 SQL 实现、读写流程或算法步骤。
- 字段名、类型、默认值和可空标记保持同类对齐；含义与约束左对齐。没有额外约束时统一使用 `—`。

**目录**

- 按实际讨论对象分组，使用「目录树｜职责」双列布局；路径与职责逐行对应。
- 左列保留缩进及 `├──`、`└──`、`│` 等树形连接符，目录以 `/` 结尾，动态名称使用一致的占位形式，如 `{project_id}`。
- 右列使用短语说明该目录或文件的用途；没有必要补充的信息留空，不为每个节点重复解释上级职责。
- 路径列保留空白和层级，职责列允许自然换行；不把目录树拆成彼此独立的卡片。

## 视觉规范

遵守用户指定的样式和当前项目已确认的视觉规范；没有另外要求时，采用以下默认值。

- 中文正文使用 `"PingFang SC", "Microsoft YaHei", system-ui, sans-serif`；技术标识使用 `ui-monospace, "SFMono-Regular", Consolas, monospace`。
- 等宽字体用于接口路径、字段名、类型、字面量和目录树；中文说明保持常规字体，不将整张表或整个页面设为等宽字体。
- 正文使用常规字重；表头和行标签使用 `500`，分组标题使用 `600`，页面标题可使用 `650`。粗体只服务于标题和必要标签，不对整句、整段或整列技术标识额外加粗。
- 使用对齐、分组、缩进、列宽与留白表达关系。一个业务分组对应一个内容区域，避免无意义的卡片嵌套。
- 表头居中，接口字段及长说明左对齐、顶部对齐；单元格使用约 `12–18px` 的纵向内边距和 `16px` 的横向内边距，字段列表项间距约 `8px`。
- 不添加宣传语、操作教程、重复摘要、冗余说明、装饰性渐变或图标。状态标记只在确有状态需要表达时出现，不用颜色或徽章制造层级。
- 窗口宽度不超过 `680px` 时，页面左右留白缩至 `16px`，标题缩至 `24px`，分组间距缩至 `24px`；保持正文字号，不通过整体缩小页面容纳内容。

| 项目 | 默认值 |
| --- | --- |
| 页面底色 | 暖米灰 `#F5F1ED` |
| 内容表面 | 暖白 `#FBF8F5` |
| 表头与次级区域 | 浅暖灰 `#F4EFEB` |
| 边框 | `1px solid #E8E1D8` |
| 主文字／正文／次级文字 | `#2A2723`／`#514B45`／`#665F57` |
| 分组圆角 | `16px` |
| 页面内容宽度 | `min(1280px, calc(100% - 48px))` |
| 页面上／下边距 | `48px`／`64px` |
| 分组间距／分组内边距 | `28px`／`20–24px` |
| 页面标题／分组标题／正文 | `28px`／`20px`／`14px` |
| 正文行高 | `1.6–1.7` |

## 交互规范

- 打开即读：交付完整 HTML，包含 UTF-8 编码、正确的页面语言、标题和 viewport；页面样式与必要交互内联，不依赖构建、开发服务器、CDN 或远程字体。
- 自动刷新：默认每 `5` 秒重新加载当前文档，使文件修改可在持续讨论中展示；不增加刷新教程或无关控制面板。
- 保留阅读位置：刷新前记录页面纵向位置、各滚动区域的横向位置和分组折叠状态；加载后先恢复折叠状态，再恢复滚动位置。
- 状态按文档和分组稳定标识隔离保存，不使用易随增删变化的分组序号作为标识。可使用 `sessionStorage`；存储不可用时仍须正常阅读和刷新。
- 横向滚动：宽表与目录树各自拥有横向滚动区域；按内容设置最小宽度，避免挤压字段或把横向溢出传递给整个页面。
- 折叠：各分组默认展开，可独立折叠正文，折叠后保留标题及已有状态；再次打开时恢复本次阅读中保存的状态。
- 折叠控件支持键盘操作，并提供正确的展开状态与控制目标；使用 `aria-expanded`、`aria-controls` 和必要的可访问名称，不用额外可见文案解释操作。

## 注释规范

- 注释指 HTML 源码中的 `<!-- ... -->`，只记录用户明确确认、属于当前讨论范围的设计约定。
- 不把 Agent 的推断、推荐或待决方案写成已确认注释；待决内容放在可见正文或交付说明的待决事项中。
- 注释专注当前文档所讨论的接口、字段、表或目录约定，不涉及实际编码逻辑、算法逻辑和顶层使用方式。
- 注释放在对应模块、表、字段或目录附近；共同约定集中记录一次，避免多处重复。
- 使用短语或短句，可压缩表达，但不得改变用户已确认的含义。

## 内容规范

- 相同语义、相同适用条件使用完全一致的文本，包括术语、句式和标点，不交替使用多个近义版本；跨行、跨分组及本次涉及的多份文档保持一致。
- 条件不同则保留差异，不为统一措辞抹掉语义；明确区分字段缺失、`null`、空字符串、空数组等已有约定。
- 一个条目表达一个含义，优先使用短语或短句；多个独立条件拆为紧凑列表，避免单元格内的大段长文本。
- 相同对象使用相同名称，相同字段使用相同路径写法；状态、枚举、单位和可选标记保持一致。
- 无字段、无默认值、无额外约束与尚未确定是不同含义，分别明确表达；不能用 `null` 或 `—` 掩盖待决问题，也不能为补齐表格编造内容。
- 已有结构足以表达关系时，不再添加解释段落；保留理解设计所必需的含义、条件和约束。

## 交付规则

- HTML 保存到用户指定的目录；未明确指定时，保存到当前项目的 `docs/` 下，文件命名遵守所在项目约定。
- 修改已有文档时更新指定文件；不擅自覆盖已确认规范，也不为排版调整复制出多份相同主题的文档。
- 交付范围止于所请求的 HTML 文档；不自动进入业务开发，不创建文档描述的接口、数据库表或业务目录。
- 最终回复按「待决事项 → 关键设计 → 文件链接」的顺序分段组织，每段使用无序列表，没有内容的段落省略。
- 文件链接提供可点击的 HTML 文件链接；待决事项只列影响当前文档的具体问题。
- 关键设计简述用户已确认的约定；业务方案建议归入待决事项，不与已确认内容混同。
