# 避免多余的防御性检查

**默认信任符合接口约定的输入。** 单字段基础约束统一通过 DTO 上的 Jakarta Validation 注解声明。校验通过后，直接执行业务流程。类型、DTO 校验或前序流程已保证的条件，禁止重复检查。

**只保留决定本次操作能否执行的业务判断。** 新增业务校验前，先问“即使输入合法，当前业务状态是否仍会阻止这次操作？”例如，资源不存在、名称重复、资源正在使用、当前状态不允许该操作，或版本、哈希发生冲突。

**开发与重构时，默认不为“假想敌”新增防御性校验。** “假想敌”指仅凭“万一发生”设想出来的异常情况，缺乏接口契约、实际业务场景或已知故障的支持。禁止为这类假设添加校验、纠正或兜底逻辑。例如，普通图片上传没有 CRC 校验要求时，无需增加 CRC 比对。参数已解析为 Java `String` 时，无需在业务层校验原始字节的 UTF-8 编码。若认为有必要在现有契约和业务规则之外增加防御性检查，应先向用户说明具体风险、现有约束为何不足，以及拟增加哪项检查，获得明确同意后再实施。
